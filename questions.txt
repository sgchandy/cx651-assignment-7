(1) Our implementation uses UDP, which does not guarantee that messages will be delivered. We also don’t have a timeout or retry mechanism, so if a message is lost, the client may end up waiting forever. If a create or join request is lost, the server never receives it, and the client keeps waiting for a response. If a move request is lost, the server does not update the game, and both players end up waiting for each other. Similarly, if a message from the server is lost, the client may not know that the game has started or that it is their turn. If a player misses the update for their own move, the game can still continue when the opponent makes the next move. However, if it was the winning move, the player may never receive the result. UDP can also deliver duplicate or out-of-order messages, which could cause issues with the game. To fix these problems, we could add timeouts and retries so clients don’t wait forever. We could also use acknowledgements to confirm messages were received and sequence numbers to identify duplicate requests.
